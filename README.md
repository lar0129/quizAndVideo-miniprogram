描述：项目通过微信小程序实现用户在线练习答题，题型只有两种：单选题和多选题。题目内容包括：题干问题、选项（大部分是ABCD四个，少量超过四个）、最终答案、解题思路的文本描述。

需求：
一 用户端：
1. 微信用户在线注册（至少包含真实姓名和电话两个信息）√
   1. 审核通过用户才能在线答题。
2. 每做一道题实时显示是否正确，并给出正确答案提示，然后选择下一题。 √
3. 用户可以查看上一次做题中做错的题目列表，允许用户重做这些做错的题。 √
4. 提供题收藏功能，供用户练习。
5. 单选和多选是分开的，用户能明显看到自己做的是单选还是多选。 √
二 管理员端
1. 后台管理员审核（通过/不通过）注册用户，要求：①可以审核单个用户，也可以批量审核（从待审核用户列表中勾选多个或者全选，一次性通过或者不通过）；②可以设置注册用户是否自动（默认通过）审核；③（通过/不通过）的用户都将收到审核结果的微信提示。
2. 统计功能：例如登录人次，已做题数量等。 
三 部署
- 不单独搭建服务器，可以采用微信云开发。协助甲方在其个人微信账号下完成部署使用。 √

# 云函数
右键./cloud/login文件夹，点击“上传并部署，云端安装依赖”。对其他云函数进行同样操作

# 数据库表单
初始化时，需创建8个集合。并在activityQuestionType中添加题目集，在activityQuestion中添加题目。

1. activityQuestion 所有题目列表。可导入/static/中的题目列表.json文件查看样例
   1. _id
   2. typeId 归属的题目集ID，需一一对应到activityQuestion中的typeId
   3. question 题干
   4. option 选项
   5. true 答案
   6. results 解题思路
   7. checked 预留字段，无意义
2. activityQuestionType 题目集
   1. _id
   2. type 题目集名称
   3. typeId 题目集ID
   4. pid 预留字段固定为"001"，便于快速替换题目集
3. WrongQuestion 错题集
   1. _id
   2. _openid 用户在微信中的唯一标识
   3. questionId 题目ID
4. activityUser
   1. _id
   2. _openid 用户在微信中的唯一标识
   3. question_num 答题数量
   4. name 用户名
   5. trueName 真实姓名
   6. phone 手机号
   7. checked 审核状态
5. test_position 答题位置
   1. _id
   2. _openid 用户在微信中的唯一标识
   3. typeId 题目集ID
   4. position 在该题目集的上次最后答题位置
